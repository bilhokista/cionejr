# Evaluation run, 2026-10-05

First execution of the 13 cases in [cases.md](../../skills/cionejr/evaluations/cases.md). One run per case. Read the limits at the end before citing any result.

## Setup

- Host: Claude Code subagents, model Claude Sonnet 5.5, one fresh session per case.
- Skill: `skills/cionejr/` v0.1.0 for the first pass; v0.1.1 for the two reruns. Each agent received a copy of the skill without the `evaluations/` folder, so it could not read the expected answers.
- Tools offered: image viewing, Python 3 with Pillow (and numpy for case 13), file writing. No internet, no graphics editor, no SVG renderer.
- Inputs: cases 01, 02, 03 and 11 used the deterministic fixtures in [fixtures/](../fixtures/); case 10 used the `bird-styles/geometric.png` sample. Case 07 used a `render.log` reporting success next to an `out.png` filled with random bytes.
- Grading: the author's agent compared each reply and its saved images with the case's Expected and Fail-if lines.

## Changes made to the skill

Rules 9 and 10 were added to `SKILL.md`, step 2 now requires a question before any generic study, and step 4 states that a detail-only request does not authorize leaving a named defect. The v0.1.1 reruns confirm those changes on the same two briefs; they say nothing about other briefs.

## Limits

- One run per case, so variance between runs is unknown.
- The agents are the same model family as the author's agent; results may not carry to other models or hosts.
- Fixtures are crude synthetic drawings built to contain one known property. Real drawings will be messier.
- The grader is an agent reading the expected-behaviour text, not a human reviewer.
- The v0.1.1 reruns were written in response to the failures, so they test the specific fix, not general robustness. The other eleven cases were not rerun on v0.1.1.
- Case 12 shows that host-installed skills can leak into a run; isolate the host before repeating it.
- None of this is a controlled before/after study of drawing quality.
